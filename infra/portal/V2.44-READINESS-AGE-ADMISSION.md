# v2.44 readiness-age admission checkpoint

Review date: 2026-10-11. Accountable owner: Gregg Clark of MGT.

The API now validates WORKER_READINESS_MAX_AGE_SECONDS before opening its production database and when createPortal is embedded directly. Production accepts decimal digits representing 60 through 86400 seconds and requires the age to be at least twice WORKER_INTERVAL_SECONDS. Preflight applies the same format and range.

The accepted production value is used without the former three-hour clamp by both /readyz and /api/hub/admin/readiness. This prevents an approved 24-hour setting from silently becoming three hours and prevents malformed values from falling back to a default.

Boundary coverage compares preflight and runtime decisions, checks the interval relationship, verifies values above the old three-hour cap, and proves the API process rejects invalid readiness ages before database initialization with a bounded diagnostic.

# v2.76 HTTP-method boundary checkpoint

The API edge now permits only `GET`, `HEAD`, `POST`, `PUT`, `PATCH`, `DELETE`, and `OPTIONS`. Protocol-oriented and extension methods such as `TRACE`, `CONNECT`, and `PROPFIND` fail closed before route or body processing.

Rejected methods receive a sanitized `405 method_not_allowed` envelope and an explicit `Allow` header. No request payload or target is logged.
